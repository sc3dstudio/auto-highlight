## Description

Paste as is. Markdown is supported.

```markdown
**Outliner Auto-Highlight keeps the active object in view.** Select something,
and the Outliner scrolls to it, opens the collections it sits in, and —
optionally — closes everything else, so a deep tree stays readable.

It is built for the moment you look at a big scene, see forty collections, and
have no idea where the object you just selected actually lives.

## What it does

- **Follows the active object.** Change the selection and the Outliner reveals
  it: parents expanded, row scrolled into view and highlighted.
- **Collapse Others** *(optional)* closes every collection that has nothing to
  do with the selection.
- **Reveal on demand** — in the Filters popover and in the operator search, for
  when you want it now instead of on the next selection change.
- Works with several Outliner editors open at once.

## Where to find it

Everything lives in the Outliner.

| Where | What |
| --- | --- |
| Outliner ▸ Filters | **Auto-Highlight**, **Collapse Others**, **Reveal Active Object Now** |
| Outliner header | the main switch as a small icon on the right |
| Operator search (`F3`) | *Reveal Active Object Now* — bind it to a key if you use it often |

The setting is stored per file, so a scene you saved with it on comes back with
it on.

## Good to know

**Blender already does part of this.** `SpaceOutliner.scroll_to_active` — "Scroll
the active item into view when it changes outside of the Outliner" — is built in,
and it expands the parent collections on its way down. If that is all you need,
switch it on under *Outliner ▸ Filters* and you can skip this add-on.

What is **not** built in is closing the collections that have nothing to do with
the selection. That is the part this adds.

**With Collapse Others on, your tree is re-arranged every time the active object
changes** — that is the feature, but it also means a tree you expanded by hand
closes again on the next selection. With the option off, the add-on only ever
reveals; it never closes anything.

**Clicking inside the Outliner counts as a selection change too.** The add-on
notices a new active object, not where the click came from, so a click in the
Outliner re-arranges the tree the same way. The object you clicked is revealed,
so the result makes sense — it just is not distinguishable from a viewport
selection.

## Requirements

Blender 4.2 or newer. Verified on 5.2.1.
```

## Checklist before submitting

1. **The repository must be public.** It is private right now. GPL-3.0-or-later
   obliges you to make the source available to everyone who gets the extension,
   and a private repository does not do that. As long as it stays private, the
   Support URL above 404s for everyone else as well. This is a decision about
   the whole repository, not about this form.
2. **Validate and install the exact zip you upload.** `validate` alone is not
   enough — it accepted an add-on whose license every older Blender rejects. See
   `tools/build_release.py` and the hermetic install recipe in
   [technical-notes.md](technical-notes.md).
3. **The screenshots are of a real session, and the tree in them belongs to a
   project file.** `assets/before.png` and `assets/after.png` show a Lamborghini
   test scene. Fine for a preview, but check that nothing in the image is
   client work.
4. **Read the description once as a stranger.** It currently says out loud that
   Blender does part of this itself. That is deliberate, and worth keeping —
   people who only wanted the scrolling should find that out before installing,
   not after.
